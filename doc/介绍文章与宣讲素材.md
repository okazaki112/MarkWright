# 一、项目拆解（源码实证）

> 以下所有结论均来自 `src/` 与 `src-tauri/` 源码实读；与文档（README）冲突处，一律以源码为准，并在文末核对表中列出差异。

## 1.1 一句话定位

**MarkWright 是一款完全本地运行的 Markdown 桌面编辑器**：把「专业级编辑体验」「写作行为沉淀」「个人知识网络」「本地加密」四件事，装进一个约 9 MB、不联网、双击即用的桌面程序里。

## 1.2 核心优势（差异化，附源码证据）

### 优势一 · 真·本地优先，无联网路径

| 维度 | 源码证据 |
|------|----------|
| 无遥测、无上报 | 全仓仅 `useHtmlToPng.ts:65` 存在一处 `fetch`，用途是导出 PNG 时把**用户自己的图片**内联为 data URL；Rust 侧无任何 HTTP 客户端（`Cargo.toml` 无 reqwest / hyper） |
| 数据落在自己的盘上 | 统计数据库 `markwright.db` 位于系统应用数据目录；会话文件 `session.json` 同目录；正文直接读写用户选择的路径 |
| 无需注册登录 | 源码中不存在账号、令牌、鉴权相关逻辑 |

> **为什么这是优势**：写作内容天然敏感（草稿、笔记、商业文档）。多数编辑器把「云同步」当卖点，而 MarkWright 把「不联网」当默认值——这不是减配，而是对「内容主权」的选择。

### 优势二 · 安全能力下沉到 Rust 侧

- 加密算法为 **AES-256-GCM**（`aes-gcm` 0.10），密钥由 `SHA-256(密码 + 固定盐)` 派生，每次加密使用 **12 字节随机 nonce**（`OsRng`）。
- 加密文件带 **`MWV1` 魔数**，解密前先校验格式，非法文件直接拒绝。
- **主密码不落前端存储**：`useVault` 只把「用密码加密后的校验串 verifier」写入 Rust 侧 SQLite；密码本身不写 `localStorage`，组件用后立即清空（`VaultDialog` 在 `finally` 中清零）。这是 0.4.8 版本专门修掉的一处安全短板。

> **为什么这是优势**：把密码学操作放在原生层、把校验物与密码本体分离存放，使得即便渲染层被注入脚本，也拿不到主密码。

### 优势三 · 把「写作行为」变成可看见的数据

- 本地 SQLite 四张表：`daily_stats`（日聚合）、`word_events`（字数事件）、`pomodoro_sessions`（番茄记录）、`settings`（配置）。
- 字数统计**不逐键写库**：增量在内存累积，**1.5 秒静默后合并上报一次**，把 IPC 次数从「每次击键」降到「每 1.5 秒一次」；切换标签或退出时强制落库。
- 可视化：**90 天写作热力图** + **近 30 天字数趋势** + 今日/本周/累计三档汇总 + 番茄钟进度。

> **为什么这是优势**：多数编辑器只告诉你「现在有多少字」，MarkWright 告诉你「你最近到底在不在写」。数据是本地算的、本地存的，不换隐私。

### 优势四 · 知识网络：双向链接 + 标签 + 反向链接

- 语法支持 `[[文件名]]` 与 `[[文件名|别名]]`，渲染为可点击的内部链接，点击即切换文档。
- 工作区扫描：**8 路并发**读取，只扫 `.md/.markdown`，单文件上限 2 MB，跳过隐藏目录与 `node_modules/target/dist`。
- 反向链接**带行号与上下文**，不是只有一个文件名列表；用 `scanToken` 作废旧轮次结果，避免并发扫描的竞态覆盖。
- 标签云按出现频次动态调整**字号与不透明度**。

> **为什么这是优势**：轻量、零依赖、纯本地实现，不引入数据库服务，也能得到接近知识库软件的关联体验。

### 优势五 · 专业编辑内核 + 可发现性设计

- 编辑器内核为 **CodeMirror 6**，具备行号、代码折叠槽、括号匹配、多光标、撤销重做、搜索、行包裹。
- **斜杠菜单**：行首或空白后输入 `/`，弹出 **21 条**语法命令（标题、粗斜体、代码、引用、列表、任务、表格、公式、目录等），支持中英文关键词筛选。
- **命令面板**：注册 **57 条**命令，分 文件 / 工作区 / 编辑 / 格式 / 视图 / 导出 / 主题 / 加密 / 专注 / 全局 / 帮助 / 模板 十二组，支持搜索与键盘导航。
- 编辑器会**主动规避误触发**：`/` 前的字符必须是行首、空白或非 ASCII，避免把 `a/b`、`http://` 当成命令。

> **为什么这是优势**：功能多不等于好用。斜杠菜单与命令面板把「知道有这功能」的门槛降到了「敲一个键」。

### 优势六 · 十二套主题 × 六个渲染维度

- `BUILTIN_THEMES` 共 **12 套**主题（深空黑、纯净白、牛皮纸、极光紫、森绿、暖阳、GitHub 暗淡、黑曜石、书卷、极地夜、抹茶、德拉库拉）。
- 每套主题不只是换颜色，而是同时定义 **6 个渲染维度**：颜色 / 字体 / 背景纹理 / 装饰 / 动效 / 信息密度。
- 正文另有 **6 个渲染家族**（modern / github / book / obsidian / nord / neon），决定标题、代码块、引用、表格、分割线的具体样式。
- 字体策略为**系统本地字体优先**，不下载外部字体（离线可用、零请求）。

> **为什么这是优势**：主题在这里是「排版系统」，而不是「换色皮肤」。

### 优势七 · 性能工程可量化

| 措施 | 源码实现 |
|------|----------|
| 预览防抖 | 输入 120 ms 合并一次；源码未变直接跳过；切标签立即渲染 |
| 重型库懒加载 | mermaid / chart.js / katex / docx 全部动态 `import`，文档里没有对应语法就**不加载** |
| 视口内渲染 | mermaid 与 chart 用 `IntersectionObserver`（预载 300 px）延迟到进入视口才渲染，并缓存结果（上限 40 条，FIFO） |
| 虚拟滚动 | `VirtualList.vue` 零依赖、固定行高、`requestAnimationFrame` 节流，超过阈值才虚拟化 |
| 资源回收 | 重渲染前统一 `dispose()` 上一轮的 Chart 实例 / Kanban 子应用 / observer |
| 构建产物 | `dist` 实测：入口约 183 KB；mermaid ≈ 668 KB、chart ≈ 203 KB、katex ≈ 257 KB 均为独立懒加载块 |

> **为什么这是优势**：一个「功能很多」的编辑器最容易死在卡顿上。这里的每一项优化都能在源码里指到具体位置。

### 优势八 · 工程细节的完整度

- **单实例 + 文件关联**：已运行时再双击 `.md`，会唤起已有窗口并把文件送进去，而不是再开一个程序。
- **图片双通道读取**：优先走资产协议（流式直读、不受插件权限限制），失败回退 Rust 直读转 data URL；读取前先用一次轻量 IPC `first_existing_path` 命中真实文件，避免对不存在的候选逐个等待 8 秒超时。
- **图片归档**：粘贴/拖入的图片自动存到**文档同级 `assets/`**，并以相对路径引用——文档搬家后引用依然成立。
- **会话恢复**：保存工作区与 UI 状态；并**刻意不恢复历史标签页**，以免与「双击打开」抢焦点（源码注释明确说明这一取舍）。
- **发布配置**：`lto`、`opt-level=3`、`codegen-units=1`、`panic=abort`、`strip` 全开。

## 1.3 核心价值

1. **内容主权**：从存储到加密，全部在用户自己的机器上闭环，不存在「服务停服、账号封禁、隐私泄露」带来的内容风险。
2. **写作可持续性**：热力图、番茄钟、环境音、易读性评分，共同服务于「让人能一直写下去」这一件事，而非堆功能。
3. **长期可迁移**：正文是标准 Markdown 纯文本，图片是普通文件，不存在专有格式锁定；换编辑器不会丢内容。
4. **零成本启动**：约 9 MB、无需注册、无需配置，双击即用。

# 二、公众号文章

> 要求：不涉及任何技术栈（不出现框架、语言、库、数据库名称）。约 1200 字。

## 标题（择一）

- 我把写作软件换成了自己写的，然后我不太想换回去了
- 一个不联网的写作软件，能好用到什么程度
- 写东西的人，最后都会在意同一件事

## 正文

先说一个我自己的经历。

我用了很多年的写作软件。它很好，功能全，界面也漂亮。直到有一天我想换一下正文字体——我在设置里翻了很久，没找到。

然后我冒出另一个念头：我写的这些东西，到底存在哪？

是不是每一次保存，都要经过某个我不知道在哪里的服务器？我的草稿、我的笔记、我还没想清楚的那些半成品，它们真的只属于我吗？

想到这儿，我就不太踏实了。

所以我做了个决定：干脆给自己写一个。

它叫 MarkWright。

### 第一件事，是它不联网

这不是「你可以手动关掉联网」，而是它从头到尾就没有联网这条路。我认真确认过：整个软件里，没有任何一处会把你的内容发出去。没有一个服务器知道你在写什么。

有多轻呢？安装包九兆多一点，双击就能用，不用注册，不用登录。你的每一个字，从键盘到硬盘，中间没有任何人。

### 第二件事，是它真的在帮你写下去

写长文最难受的，往往不是没灵感，是坐不住。

所以我给它做了一个专注模式。按一下，所有界面消失，屏幕上只剩你的文字，中间一个圆环慢慢倒计时，二十五分钟专注，五分钟休息。右下角还能放一段环境音，雨声、咖啡馆、键盘、森林，四种任选。

有意思的是，它一个音频文件都没有——那些声音是当场用算法算出来的。

它还会悄悄记一些东西：你今天写了多少字，这周写了多少，一共写了多少，画成一张九十天的热力图。你哪天在偷懒，一眼就能看出来。它默认给你定的目标是每天五百字、四个番茄，当然你也能自己改。

### 第三件事，是它记得住你写过的所有东西

写到几十篇、上百篇的时候，真正的难题不是写不出来，是找不回来。

所以它把你的每一篇稿子连成一张网。你在文里写两个方括号加一个文件名，它就自动变成一条可以点的链接，一点就跳过去。反过来，它也会告诉你，你正在看的这一篇，被哪些别的文章引用过，甚至能定位到具体那一行。

你打的那些标签也一样，它会自动收集起来，做成一个标签云——出现得越多的标签，字号越大。写得越多，这张网就越清楚。

### 第四件事，是它能陪着你好看

它准备了十二套主题。从深空黑到牛皮纸，从极光紫到抹茶绿。而且换一套主题，不只是换个颜色——连正文字体、背景的纹理、标题的装饰、甚至动画的节奏，都会一起变。

写累了换个皮肤，心情真的会不一样。

### 最后，回到开头那个问题

它内置了一个本地加密的功能。

你可以给稿子设一个主密码。按一下，文件就变成一堆谁也读不懂的乱码，后缀也变了。别人拿到这个文件，没有密码，打不开。

我要特别说一句：你的密码，它只存在你自己的电脑上，用完就从内存里清掉，不会写到任何别的地方。也正因如此——密码丢了，是真的找不回来。这一点，一定要想清楚。

### 写在最后

它不是大厂做的。它就是我一个人，一行一行写出来给自己用的。

所以它可能没有那么花哨，但每一个功能，都是我写作的时候真的需要，才做出来的。

如果你也是一个喜欢安静写字的人，那我觉得，它可能会挺合你胃口。

# 三、口播逐字稿（约五分钟）

如果你也是一个喜欢安静写字的人，那我觉得，它可能会挺合你胃口。具体的下载方式我放在简介里了。那我们，下期见。
